# 51–100단계 준비와 공개

51–100단계는 모두 제작했지만 현재 공개 상한은 50입니다. 소유자가 실제 업데이트를 요청할 때마다 10단계씩 공개합니다. GitHub에 작업을 보관하는 것과 운영 게임에 배포하는 것은 별도입니다. 공개 일정과 자동 배포 예약은 없습니다.

| 묶음 | 주제 | 원본 데이터 |
| --- | --- | --- |
| 51–60 | 직사각형 입문 | `content/stages-51-60.json` |
| 61–70 | 직사각형 심화 | `content/stages-61-70.json` |
| 71–80 | 계단형 입문 | `content/stages-71-80.json` |
| 81–90 | 여러 모양 교차 | `content/stages-81-90.json` |
| 91–100 | 모양과 낙하의 마무리 | `content/stages-91-100.json` |

각 파일에는 숫자, 별 위치, 행·열, 제한 횟수, 정답 경로, 최소 수, 가능한 첫 연결과 성공하는 첫 연결 수, 낙하 활용 지표가 들어 있습니다. 경로의 좌표는 0부터 시작하는 행 우선 인덱스이며 매 이동 후 낙하한 판을 기준으로 합니다. 정답 전체와 검증 지표는 배포용 데이터에서 제외합니다.

도입과 매 여섯 번째 쉼표는 최소 2수에 제한 3수로 준비했습니다. 응용은 3수, 종합은 4수 중심입니다. 5×5는 95·99단계에만 배치했습니다. 100단계는 4행 5열에서 별 없는 연결을 먼저 지우고, 낙하와 등차·등비 전환을 함께 이용해야 풀립니다. 자동 검증은 논리적인 해결 가능성을 확인하며 사람의 체감 난도는 플레이 피드백에 따라 조정할 수 있습니다.

## 공개 전 미리 보기

```sh
npm run preview:stages
```

이 명령은 100단계까지 포함한 테스트 복사본을 `work/preview/`에 만듭니다. 해당 폴더를 로컬 정적 서버로 열고 `/?stage=75`처럼 단계 번호를 지정하면 메인의 시작하기가 해당 판으로 이어집니다. 테스트 복사본은 해당 서버 출처의 진행 기록을 테스트용으로 덮어쓰고 힌트를 엽니다. 운영 사이트와 다른 로컬 주소에서만 사용하세요. 이 폴더는 Git에서 제외되며, 정식 배포 폴더 `dist/`와 공개 상한은 바뀌지 않습니다.

## 소유자가 다음 열 단계를 공개하라고 했을 때

예를 들어 현재 50단계에서 51–60단계를 공개할 때:

```sh
npm run release:stages -- --to 60
npm test
```

이 명령은 공개 상한을 60으로 바꾸고, 51–60단계의 실행 데이터와 정답으로 이어지는 첫 수 힌트를 생성하며 오프라인 캐시를 갱신합니다. 이후 동일하게 70, 80, 90, 100 순서로 실행합니다. 중간 단계, 두 묶음 건너뛰기, 되돌리기와 101 이후는 거부합니다. 명령 자체는 GitHub에 푸시하거나 배포하지 않습니다.

변경분과 테스트를 검토한 뒤 요청된 업데이트만 운영 브랜치에 반영하고 기존 배포 절차를 따릅니다. 운영 브랜치 푸시에 호스팅 자동 배포가 연결되어 있다면 이 푸시가 실제 공개라는 점에 주의합니다. 콘텐츠 준비 브랜치를 올리는 것만으로 운영 브랜치를 병합하지 않습니다.

매 공개 시 확인할 내용:

- 기존 완료 기록을 가진 플레이어가 새 구간의 첫 미완료 단계로 이어지는지 확인합니다.
- 공개된 마지막 단계에서 업데이트 예정 화면이 나타나는지 확인합니다.
- 설치 앱의 업데이트 후 기존 진행 기록이 유지되는지 확인합니다.
- 실제 휴대폰에서 새 구간의 대각선·꺾기 입력과 실패·재도전을 확인합니다.

## 판 규칙과 검증

`n`은 기존 호환성을 위해 열 수를 뜻하며 행 수는 `board.length / n`입니다. 계단형의 각 열은 맨 아래부터 연속으로 채워져 있습니다. 낙하는 같은 열에서만 일어나며 새 타일이 생기지 않으므로 빠진 상단 칸을 채울 수 없습니다. `mask`는 빠진 칸을 빈 슬롯과 구분해 표시합니다. 중간 구멍과 떠 있는 칸은 허용하지 않습니다.

`npm test`는 기존 50개 판의 전체 데이터 해시 보존, 새 50개 판의 최소 수와 첫 연결 선택, 정답 재생, 계단형 마스크, 낙하, 터치 좌표, 힌트, 실패·재시작과 모든 10단계 경계의 진행도 보존을 검사합니다. 일반 빌드도 `content/release.json`과 실제 공개 데이터가 일치하는지 검사합니다. 미공개 JSON은 웹 루트와 오프라인 캐시에 포함되지 않습니다. GitHub 저장소 자체는 공개 저장소이므로 원본 데이터는 GitHub에서 볼 수 있습니다.

새 판 재생성은 `npm run generate:shapes`로 수행합니다. 고정 시드와 판별 조건을 사용하지만 이미 공개한 판은 소유자의 수정 요청 없이 재생성하지 않습니다. 101단계 이후의 서리는 이번 구현에 포함하지 않았습니다.

## 이번 준비본의 확인 결과

2026년 9월 22일 기준 자동 검사 191개를 통과했습니다. 배포 명령은 별도의 복사본에서 60→70→80→90→100을 차례로 생성하고 공개 데이터·힌트·오프라인 캐시의 일치를 확인했습니다. 실제 작업본의 공개 상한은 50으로 유지했습니다.

브라우저에서는 390×844 화면의 51단계 가로 드래그와 꺾기 연결, 75단계 계단형 표시·힌트·클리어를 확인했습니다. 320×640 화면에서 99단계 타일 폭은 약 48픽셀이었고 가로 넘침이 없었습니다. 99→100 이어하기, 100단계 클리어 후 업데이트 예정 화면도 확인했으며 브라우저 오류 로그는 없었습니다. 실제 휴대폰 손가락 입력과 사람의 체감 난도 평가는 공개 전 점검 대상으로 남습니다.
